Gitwise

A practical guide to choosing the right Git tool for the situation. Click any topic to see when to use it and a few starting commands.

← Back to Tin's site
1
BranchesIsolate a feature, experiment, or fix without disturbing the main branch

Use a branch whenever work may need review, may take more than one commit, or should be easy to abandon. Keep the main branch stable.

git switch -c feature-namegit switch main
2
ReflogRecover lost commits and inspect where HEAD used to point

Use the reflog after a reset, rebase, deleted branch, or other mistake when a commit seems to have disappeared. It records local reference movement.

git refloggit reset --hard <commit>
3
Merge ConflictsCombine histories when both branches changed related lines

Use a merge when you want to preserve both branch histories and bring completed work into another branch. Resolve each conflict, test, then commit.

git merge feature-namegit add .git commit
4
Rebase ConflictsReplay your commits on a newer base while keeping history linear

Use rebase before sharing a branch when you want a clean, linear history. Do not rebase commits that other people are already building on without coordination.

git rebase maingit rebase --continuegit rebase --abort
5
SquashTurn a noisy sequence of work-in-progress commits into a reviewable change

Squash before merging when intermediate commits are implementation notes, fixes to fixes, or unrelated clutter. Keep meaningful milestones when they help explain the history.

git rebase -i HEAD~N
6
StashTemporarily put aside uncommitted work when you need a clean tree

Use stash for short interruptions—such as switching branches to inspect a bug. For substantial work, a temporary branch is usually safer and easier to find later.

git stash push -m "work in progress"git stash pop
7
RevertSafely undo a published commit without rewriting shared history

Use revert on shared branches or after a commit has been pushed. It creates a new commit that reverses the earlier change.

git revert <commit>
8
Cherry-pickSelectively move one or more commits from another branch

Use cherry-pick for a targeted bug fix, backport, or small change that should move without merging an entire branch. Check for conflicts and duplicate work.

git cherry-pick <commit>
9
BisectFind the commit that introduced a regression through binary search

Use bisect when you know a good revision and a bad revision but do not know which commit caused the problem. Mark each checked revision as good or bad.

git bisect startgit bisect goodgit bisect badgit bisect reset
10
WorktreesWork on multiple branches at once in separate directories

Use worktrees when you need to keep a long-running feature open while reviewing a pull request, testing a hotfix, or running another branch locally.

git worktree add ../project-hotfix hotfixgit worktree list
11
TagsMark stable versions and release points so they can be found again

Use annotated tags for releases, published versions, and other durable milestones. Push tags deliberately when they should be visible to collaborators.

git tag -a v1.0.0 -m "Release v1.0.0"git push origin v1.0.0
